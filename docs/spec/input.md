# spec: 入力

- 所有範囲：ナラティブの項目と形式、自由入力の形式、個人情報の検出規則

## 1. 入力の種類

| 種類 | 置き場所 | 形式 |
|---|---|---|
| ナラティブ | `<STORYTELLER_HOME>/inputs/narratives/*.json` | 13項目のJSON（§2） |
| 自由入力 | `<STORYTELLER_HOME>/inputs/free/*.md` | 自由な Markdown またはテキスト（§3） |

どちらも S0 で `input.json` に正規化する（[story-pipeline.md](story-pipeline.md) S0）。

## 2. ナラティブ

### 2.1 原則

ナラティブに書くのは、**ユーザーがどのような傾向を持っているか**だけである（P8、[ADR-0006](../adr/0006-no-pii-in-narrative.md)）。
具体的な出来事・人物・場所・日付ではなく、それらを通じて繰り返し現れる「感じ方・惹かれ方・恐れ方・抑え方」を書く。

### 2.2 項目

項目は heros-journey の13項目を引き継ぎ、問いを「傾向」を書く形に改める。値はすべて文字列、各300字以内とする。JSON Schema は `schemas/narrative.schema.json`。

| キー | 項目名 | 問い | 書かないこと |
|---|---|---|---|
| `author` | 人となり | あなたは、どのような傾向を持つ人ですか | 職業名・所属・年齢・居住地 |
| `missing` | 欠落 | 自分に欠けていると感じがちなものは何ですか。それは何を象徴していますか | |
| `status` | 現在地 | その欠落に対して、今どのような状態にあると感じていますか（満たされた／かつては／まだ／わからない） | |
| `memories` | 形成 | 今の傾向をつくったのは、どのような種類の経験ですか | いつ・どこで・誰と、の具体 |
| `mission` | 使命 | 欠落を埋めるために、何をしなければならないと感じていますか | |
| `success` | 成功像 | 満たされた状態とは、どのようなものだと思いますか | |
| `loss` | 代償 | そのためなら失ってもよい、または失うのが怖いものは何ですか | |
| `taboo` | 禁忌 | 越えたくない一線は何ですか | |
| `inhibit` | 抑制 | 自分を抑えているものは何ですか | |
| `daily` | 日常 | 普段の日常は、どのような質感のものですか | 勤務先・通勤経路・生活圏の地名 |
| `change` | 変化の契機 | どのようなことがあると、自分は変わると思いますか | |
| `acceptance` | 受容 | 受け入れられること、受け入れにくいことは何ですか | 特定の人物への言及 |
| `desire` | 秘めた願望 | 誰にも話していない願望は何ですか | |

- 空欄の項目は、空文字列のまま扱う。サンプル値で補完しない（ユーザーのものではない内容を混ぜないため）。
- 13項目のうち、空でない項目が3つ未満のナラティブは取り込まない（素材が少なすぎ、要素テーブルの比重が過大になるため）。
- 記入ガイドとして、項目ごとの記入例（良い例・書きすぎの例）を `docs/guides/narrative.md` に置く（P2-02）。

## 3. 自由入力

- 形式は問わない。物語の着想、断片、箇条書き、テーマの一言でもよい。
- 空行で区切られたまとまりを1段落として扱い、S1 は段落ごとにタスクを作る。1段落が 1200字を超える場合は、文末記号の位置で 1200字以内に分割する。
- 全体で 20000字を超える自由入力は取り込まない。

## 4. 個人情報の検出

取り込み時（`st new`, `st check-input`）に、コードで次を検出する。LLMには判定させない。

| 検出対象 | ナラティブ | 自由入力 |
|---|---|---|
| メールアドレス | 検出する | 検出する |
| 電話番号（国内・国際形式） | 検出する | 検出する |
| 郵便番号（`〒`、`NNN-NNNN`） | 検出する | 検出する |
| URL（`http(s)://`、`www.`） | 検出する | 検出する |
| SNSハンドル（`@` に続く英数字） | 検出する | 検出する |
| 住所表記（都道府県名＋市区町村名、丁目・番地・号） | 検出する | 検出する |
| 7桁以上の連続した数字 | 検出する | 検出する |
| 具体的な年月日 | 検出する | 検出しない |

- 自由入力で日付を検出しないのは、物語の着想には架空の日付や年代が自然に含まれるためである。ナラティブは傾向を書くものであり、具体的な日付を必要としない。
- 1件でも検出されたら、取り込みを拒否し、項目名（または段落番号）・文字位置・検出種別を表示する（終了コード 4）。検出された文字列そのものは、画面・ログ・ファイルに書き出さない。
- 検出の例外指定は設けない。誤検出された場合は、ユーザーが表現を変える（例：「3024年」→「遠い未来」）。例外指定は、個人情報を通す抜け道になるためである。
- 人名・組織名は確実には検出できない。記入ガイドで「固有名詞を書かない」ことを明示する。
