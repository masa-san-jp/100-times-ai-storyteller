# spec: 実行者プロトコル

- 所有範囲：実行者が従う手順と禁止事項

`st workspace init` が実行者ワークスペースに書き出す `AGENTS.md` / `CLAUDE.md` は、この文書の §2 から生成する。この文書を変更したら、テンプレート（`src/storyteller/workspace_template/`）も同じ変更で更新する。テンプレートとこの文書の §2 が一致していること、§2 に書いた終了コードが [cli.md](cli.md) §3 と一致していることは、テストで検査する。

## 1. 対象

コーディングエージェントなど、自分でコマンドを実行できる実行者。ローカルLLM（`st auto`）とチャットモデル（手動）は、このプロトコルを読まない。オーケストレータとアダプタ、または人間が同じ手順を代行する。

## 2. プロトコル（ワークスペースに書き出す本文）

```markdown
# あなたの仕事

あなたは、タスクを1つずつ実行する実行者です。次の手順を繰り返してください。

1. `st next --wait 600` を実行し、タスクカードを受け取る。
   - 終了コード 2（10分待ってもタスクがない）なら、作業を終える。
2. タスクカードに書かれた「入力」「手順」「出力形式」だけに従って、出力を作る。
3. 出力をこのワークスペースの `out.txt` に保存し、`st submit <ticket> out.txt` を実行する。<ticket> はタスクカードの見出しに書かれている。
   - 終了コード 5（不合格）なら、手順1に戻る。同じタスクが、不合格の理由つきで再び渡されることがある。
   - 終了コード 3（claim が無効）なら、手順1に戻る。
   - 0・2・3・5 以外の終了コードなら、作業を終え、最後に実行したコマンドと出力を報告する。
4. 手順1に戻る。

# 守ること

- タスクカード以外のファイルを読まない。このワークスペースの外にあるファイルを開かない。
- タスクカードに書かれていない情報・設定・出来事を、出力に加えない。
- 物語全体がどうなるかを推測しない。前後のタスクを先回りしない。
- 出力形式以外の文章（説明・前置き・感想）を出力に含めない。
- 複数のタスクの内容をまとめたり、比較したりしない。
```

## 3. 待ち時間の扱い

- LLMタスクがない時間は、他の実行者が依存タスクを処理している間に生じる。コードタスクは即時に実行されるため、待ちの原因にはならない。
- 10分待ってもタスクがない場合に終了するのは、run がすべて完了または停止している状態で、実行者が待ち続けて資源を使い続けないようにするためである。無人運転で実行者を再起動する仕組みは、Phase 4 で `st auto` と運用手順に定める。
