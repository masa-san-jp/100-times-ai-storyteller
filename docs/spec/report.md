# spec: バッチの傾向分析

- 所有範囲：`st report` の処理、入力・出力、分析の原則

## 1. 目的と原則

同じ入力から生成したバッチの正本に、どのような傾向が現れたかを、ユーザーが振り返るための材料を出力する（heros-journey の batch_analyzer を継承）。

- 分析は解釈を押し付けるためのものではない。断定や診断をせず、正本の実例に基づく傾向を示す。元の入力との関係は、問いの形で示す。
- LLM に正本の全体を読ませない（P1・P5）。LLM が読むのは、コードが切り出した、文字数予算内の抜粋だけとする。
- 分析は、バッチのディレクトリ `batches/<batch_id>/report/` に、run と同じ構成の manifest とタスクを持つ（[data-layout.md](data-layout.md) §2）。タスクは `st next` の対象になる。

## 2. 処理

| # | 段階 | 種別 | 内容 |
|---|---|---|---|
| R1 | 集計 | [C] | バッチの `completed` の run について、プロット型・入力由来の比率・割り当てた要素・役の出現回数を集計する |
| R2 | run ごとの要約 | [C]+[L] | [C] 主人公の願望・敵対者の役割は `assignment.json` から取り出す。[L] 1タスク = run 1つ。入力は、主筋の出来事の `what` と `result` を時系列に並べたもので、文字数予算を超える場合は先頭と末尾を残して中間を省く。出力：`{"central_loss", "ending", "motifs": [最大5]}`（各60字以内） |
| R3 | モチーフの集約 | [C] | R2 の `motifs` を正規化し、文字3-gram の類似度でまとめ、出現した run が多い順に最大7群を選ぶ |
| R4 | 問い | [L] | 1タスク = モチーフ1群。入力は、群の代表語と、その群が出現した run の R2 の要約3件まで。出力：`{"observation": "1文", "question": "1文"}`。`question` は、入力とのつながりを問う疑問文とする |
| R5 | 組み立て | [C] | `batches/<batch_id>/report/report.md` と `report.json` を出力する。各記述に、根拠となった run ID を付ける |

## 3. 出力

- `report.json` の形式は `schemas/report.schema.json` とする。
- `report.md` は、集計表（R1）、モチーフ群と問い（R3・R4）、run ごとの要約の一覧（R2）の順に並べる。
