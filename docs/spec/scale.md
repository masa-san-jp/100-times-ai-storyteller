# spec: 物語の規模

- 所有範囲：規模の軸、規模プリセット、軸の上書き、出来事数の決め方、規模からの派生値

§2・§3 の値の表、§4 の段階ごとの最小出来事数、§6 の世界セクションの対応は [`tables/scales.yaml`](../../tables/scales.yaml) を原本とする（[docs/README.md](../README.md) §2.1）。

## 1. 原則

ユーザーが指定するのは、**出力文字数ではなく物語の規模**である（[ADR-0005](../adr/0005-scale-not-length.md)）。
規模は「どれだけの時間・空間・人物・筋にわたって、何がどこまで変わる物語か」で表す。
出来事数・人物数・必要な世界設定・様式化したときの分量は、すべて規模からコードが導く。

## 2. 規模の軸

各軸は、[`tables/scales.yaml`](../../tables/scales.yaml) に小さい方から段階0〜4の値を持つ。

## 3. 規模プリセット

規模プリセット（`vignette`、`short`、`novella`、`novel`、`saga`）の軸と出来事数の範囲は、[`tables/scales.yaml`](../../tables/scales.yaml) に定義する。


## 4. 出来事数の決め方

1. 各軸の段階から、その軸が要求する最小出来事数を [`tables/scales.yaml`](../../tables/scales.yaml) の `level_min_events` で求める。
2. 下限 = 次の大きい方。
   - 全軸の最小出来事数の最大値
   - 3 + 6 × 副筋の最大数（主筋に最低3件を残し、副筋1本あたりの上限6件を確保するため。副筋は [story-pipeline.md](story-pipeline.md) §4.3）
3. プリセットの出来事数の範囲 `[a, b]` について：
   - `a ≥ 下限` なら、範囲はそのまま。
   - `a < 下限` なら、範囲を `[下限, ceil(下限 × 1.33)]` に引き上げ、manifest の `warnings` に記録する。
4. 範囲の中から、run の seed で出来事数を決める。
5. 大河は、部ごとに 1〜4 を行う。

軸どうしの組み合わせを禁止する規則は設けない。一見ちぐはぐな組み合わせ（例：15人以上が一か所に集まる物語）も物語として成り立ちうる。成立に必要な分量は、下限の引き上げによって確保する。

## 5. 軸の上書きと部数

- プリセットを基準に、個々の軸を `--axis KEY=VALUE` で上書きできる（例：`--scale short --axis time=generations`）。
- `threads=parts` のとき、部数は `--parts N`（2〜6）で指定する。省略した場合は、run の seed で 2〜4 から決める。
- `threads=parts` 以外で `--parts` を指定した場合はエラーにする。

## 6. 規模から導かれる値

| 派生値 | 決め方 | 使う段階 |
|---|---|---|
| 出来事数 | §4 | S3, S6 |
| 筋の数 | `threads` の段階から、範囲内で seed により決める | S3 |
| 人物の数 | `cast` の範囲内で seed により決める | S3 |
| 役 | [story-pipeline.md](story-pipeline.md) S3 の手順5 | S3 |
| 筋ごとの構造テンプレート | プロット型と、筋に配分された出来事数から決める（[story-pipeline.md](story-pipeline.md) §4.2） | S3 |
| 生成する世界セクション | `space` と `change` の段階の大きい方を n として、[`tables/scales.yaml`](../../tables/scales.yaml) の `world_sections_by_level` にある段階0から n までのセクションをすべて生成する（累積） | S4 |
| 要素プールの必要量 | 軸ごとに、S3 で割り当てる個数 × 3（候補倍率） | S2 |
| 資料と物語の分量 | 最低ライン（ADR-0007）× `volume_multiplier`。配分は [story-pipeline.md](story-pipeline.md) §8 | S0, S3, S6 |
| 様式化したときの分量 | 様式プロファイルの「出来事1件あたりの分量」× 出来事数 | F0 |

派生値はすべて `st new` の時点で計算し、manifest に記録する。

## 開発用の規模 `dev`（[ADR-0009](../adr/0009-never-stop-and-verify-small.md)）

- 開発の確認だけに使う規模で、ユーザー向けの規模プリセットには含めない。`st new --scale dev` で指定する。
- すべての種類の LLM タスクを1回以上含み、本物のモデルで数分で終わる大きさとする：世界は単一型・一覧型のセクションを各1つ（観点1つ・面1つ、一覧の項目1件）、人物2人、筋1本・出来事3件（最小の構造テンプレート `three-beat` の各段階に1件ずつ置ける最小の数）、出来事ごとの場面1つ。
- 値（軸・出来事数・人物数・世界セクション・観点数・一覧の項目数・素材数・候補倍率・事実の範囲と反復件数・確認用字数）は [`tables/scales.yaml`](../../tables/scales.yaml) の `dev` を原本とする。`--axis` と `--parts` は指定できない。
- `tools/dev_run.sh` が `dev` の run を作り、指定の実行者で最後まで回して、所要時間と `skipped`・`warnings` を表示する。
- 分量の最低ライン（ADR-0007）は適用しない。`dev` では `tables/scales.yaml` の確認用字数を配分と検証の両方に使う。すべての物語生成LLMタスク種別、事実と意味の検証、修正・継続・省略の経路は残す。本番プリセットの字数と検証は変更しない。
- 素材は段落ごとの確認用件数に限る。S2 は候補倍率から求めた必要量だけを生成し、余分な組を作らない。対極要素は生成した要素を入力に作る。
- 確認用の描写カードに字数範囲 `output_chars` を作り方の指示として渡す。この範囲を正規化した入力とキャッシュキーにも含め、本番の出力を短い確認用カードに誤再利用しない。
- 確認用の世界の事実は、`dev.world_fact_keys` で指定した確認用キーのうち実際に描くセクション・一覧項目に属するものを選び、そこから参照する事実の再帰閉包を含める。キーは世界の事実カタログを参照し、型・範囲・参照を変更しない。未知のキーや確認用の対象に属さないキーは設定不正として検出する。選択後も生成した事実の全体に対する整合性検証を行う。人物の scalar 事実は全項目を残し、家族・年表・技能の反復件数だけを `dev.character_fact_counts` の最小件数に固定する。本番の事実の範囲と乱数による件数は変更しない。

- `dev.event_candidates` は `what` の候補数だけを上書きする。複数候補を残し、選択は従来と同じCODEで行う。本番の候補数・選択・seed付き乱数の割当は変更しない。確認用の字数と世界の事実キーの値は `tables/scales.yaml` を原本とし、描写・動機を短くしても、全LLM種別と人物の全scalar事実・項目は残す。
