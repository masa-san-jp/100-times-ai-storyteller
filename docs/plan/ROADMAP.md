## Phase 0：基盤
- 目的：LLMを使わずに、タスクDAGが最後まで進む仕組みを、3つの OS で動く形で作る。
- 完了条件：
  1. 固定の応答を返すダミー実行者で、コードタスクとLLMタスクを含むダミーのDAGが最後まで進む。
  2. 2つのプロセスが同時に `st next` を実行しても、同じタスクを二重に claim しない。
  3. lease が切れたタスクを、別の実行者が claim し直せる。
  4. 途中でプロセスを止めても、再実行で続きから進む。
  5. 不合格の出力が理由つきで再試行され、上限で `failed` になる。
  6. 1〜5 のテストが、CI の macOS・Linux・Windows すべてで通る。

## Phase 1：最小の物語生成（自由入力 × 掌編・短編）
- 目的：自由入力から正本までを、実際のLLMで end-to-end に通す。
- 完了条件：
  1. 20B前後のローカルモデルで、自由入力から短編の正本が、人間の介入なしに出力される。
  2. Claude Code と Codex が、実行者ワークスペースから同じ手順で正本まで完走できる。
  3. すべてのLLMタスクのカードが `max_input_chars` 以内に収まっている。
  5. 正本が分量の最低ライン（人物10,000字・世界100,000字・物語100,000字、ADR-0007）を満たす。
  4. Claude Code と Codex の実行者が、ワークスペースの外のファイルを読もうとすると、権限設定によって拒否される。

## Phase 2：ナラティブと多様性
- 目的：ナラティブを取り込み、同じ入力から多様な物語を生成できるようにする。全規模に対応する。
- 完了条件：
  1. 同じナラティブから10本の正本を生成したとき、重複・近似重複と判定されるものがない。
  2. そのとき S1・S2 は1回ずつしか実行されていない。
  3. 個人情報を含むナラティブの取り込みが拒否される。
  4. 5つの規模プリセットと21のプロット型それぞれで、正本が出力される。

## Phase 3：様式化
- 目的：正本から、ユーザーが選んだ様式で物語を出力する。
- 完了条件：
  1. 1つの正本から、小説・映画シナリオ・プレゼンテーションの3様式が出力される。
  2. 各様式の分量が、規模と様式プロファイルから計算した範囲に収まっている。
  3. 映画シナリオが Fountain として、プレゼンテーションが Marp として構文検査に通る。

## Phase 4：並列・無人運転
- 目的：人間がいない間に、複数の実行者で多数の物語を完了させる。
- 完了条件：
  1. 複数の実行者を無人で8時間以上動かし、途中で落ちた実行者がいても、全 run が `completed` か `stalled`（理由つき）になっている。
  2. バッチの傾向分析が出力される。

## Phase 5：拡張
- 目的：系譜上の工程（画像プロンプト・資料集）を様式として加え、テーブルの保守と評価の手段を整える。
- 完了条件：[phase-5.md](phase-5.md) の作業項目がすべて完了している。
