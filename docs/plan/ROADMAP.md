# ROADMAP：開発フェーズ

- 所有範囲：開発フェーズの目的・範囲・完了条件・順序と、各フェーズの状態

各フェーズは、完了条件をすべて満たした時点で終了とし、次のフェーズへ進む。作業項目は各フェーズの計画書に置く。

| フェーズ | 名前 | 計画書 | 状態 |
|---|---|---|---|
| 0 | 基盤 | [phase-0.md](phase-0.md) | 完了 |
| 1 | 最小の物語生成 | [phase-1.md](phase-1.md) | 完了 |
| 2 | ナラティブと多様性 | [phase-2.md](phase-2.md) | 進行中 |
| 3 | 様式化 | [phase-3.md](phase-3.md) | 完了 |
| 4 | 並列・無人運転 | [phase-4.md](phase-4.md) | 未着手 |
| 5 | 拡張 | [phase-5.md](phase-5.md) | 未着手 |

状態は `未着手` / `進行中` / `完了` とし、フェーズの開始時と完了時に更新する。

## 開発の進め方（[ADR-0009](../adr/0009-never-stop-and-verify-small.md)）
- 作業項目の受け入れ条件には、開発用の最小規模（`dev`）の実機の run が、止まらずに最後まで通ることを含める。`dev` の run は本物のモデルで数分で終わる。
- 分量の最低ライン（ADR-0007）を満たす run は、各フェーズの完了時に1回だけ行う。
- run は1つのタスクの不合格で止めない（task-model §6.7）。止まった場合はハーネスの欠陥として Issue にする。
- 開発と確認の run は、所有者の端末が眠っていても進む環境で回す。所有者に見張りや承認を求めない。所有者への報告は、フェーズの完了時に結果のページで行う。

## Phase 0：基盤
- 目的：LLMを使わずに、タスクDAGが最後まで進む仕組みを、3つの OS で動く形で作る。
- 完了条件：
  1. 固定の応答を返すダミー実行者で、コードタスクとLLMタスクを含むダミーのDAGが最後まで進む。
  2. 2つのプロセスが同時に `st next` を実行しても、同じタスクを二重に claim しない。
  3. lease が切れたタスクを、別の実行者が claim し直せる。
  4. 途中でプロセスを止めても、再実行で続きから進む。
  5. 不合格の出力が理由つきで再試行され、上限で `failed` になる。
  6. 1〜5 のテストが、CI の macOS・Linux・Windows すべてで通る。

## Phase 1：最小の物語生成（自由入力 × 掌編・短編）
- 目的：自由入力から正本までを、実際のLLMで end-to-end に通す。
- 完了条件：
  1. 20B前後のローカルモデルで、自由入力から短編の正本が、人間の介入なしに出力される。
  2. Claude Code と Codex が、実行者ワークスペースから同じ手順で正本まで完走できる。
  3. すべてのLLMタスクのカードが `max_input_chars` 以内に収まっている。
  4. Claude Code と Codex の実行者が、ワークスペースの外のファイルを読もうとすると、権限設定によって拒否される。
  5. 正本が分量の最低ライン（人物10,000字・世界100,000字・物語100,000字、ADR-0007）を満たす。
  6. `dev` 規模の run が、ローカルモデルとクラウドのモデルの両方で、止まらずに `completed` になる。不合格のタスクが手直し・格上げ・記録によって処理され、run が `stalled` にならない（ADR-0009）。所要時間は記録するが、合否の条件にしない（`dev` は欠陥を早く見つけるための確認であり、速度は製品の要件ではない）。

## Phase 2：ナラティブと多様性
- 目的：ナラティブを取り込み、同じ入力から多様な物語を生成できるようにする。全規模に対応する。
- 完了条件：
  1. 同じナラティブから10本の正本を生成したとき、重複・近似重複と判定されるものがない。
  2. そのとき S1・S2 は1回ずつしか実行されていない。
  3. 個人情報を含むナラティブの取り込みが拒否される。
  4. 5つの規模プリセットと21のプロット型それぞれで、正本が出力される。

## Phase 3：様式化
- 目的：正本から、ユーザーが選んだ様式で物語を出力する。
- 完了条件：
  1. 1つの正本から、小説・映画シナリオ・プレゼンテーションの3様式が出力される。
  2. 各様式の分量が、規模と様式プロファイルから計算した範囲に収まっている。
  3. 映画シナリオが Fountain として、プレゼンテーションが Marp として構文検査に通る。

## Phase 4：並列・無人運転
- 目的：人間がいない間に、複数の実行者で多数の物語を完了させる。
- 完了条件：
  1. 実行者の異常終了を途中で混ぜた dev 規模のバッチ10本が、人の手なしですべて完走している（`completed`、または重複判定の `duplicate`。`skipped` のタスクは理由つきで記録されている）。長時間の運転は運用手順（[operations.md](../guides/operations.md)）に従って所有者が行う。
  2. バッチの傾向分析が出力される。

## Phase 5：拡張
- 目的：系譜上の工程（画像プロンプト・資料集）を様式として加え、テーブルの保守と評価の手段を整える。
- 完了条件：[phase-5.md](phase-5.md) の作業項目がすべて完了している。
