# ADR-0007：資料と物語の分量の最低ラインを定める

- 状態：Accepted
- 日付：2026-10-01

## 背景
最初の完走例（短編、gpt-oss:20b）の正本は約12,000字で、人物・世界・物語のいずれも、作品の素材として分量が圧倒的に足りなかった。所有者が最低ラインを定めた。

## 判断
物語の規模によらず、1本の run は次の分量を最低ラインとして持つ。中編・長編・大河では、規模に応じてさらに増やす（倍率は `tables/scales.yaml`）。

| 資料 | 最低ライン |
|---|---|
| 人物に関する資料 | 10,000字以上（全人物の合計） |
| 世界に関する資料 | 100,000字以上 |
| 物語（正本の出来事の記述） | 100,000字以上 |

分量は正本（説明的な物語と資料）の分量であり、小説などの様式化はその上に行う。

## 理由
- 物語の素材として、人物・世界・出来事の厚みが作品の質を決める。先行リポジトリ（world-building）も、100倍拡張によって大量の資料を生成していた。

## 影響
- 1タスクの出力を短く保つ原則（P5）は変えない。タスクを細かく分け、数を増やして分量を積み上げる。1本の run の LLM タスクは数百件になり、ローカルのモデルでは数時間かかる。
- [ADR-0005](0005-scale-not-length.md)（ユーザーは文字数ではなく規模を指定する）は変えない。分量の最低ラインは、規模とは別に、すべての run に適用する。
- 分量の配分と、それを満たすタスクの組み立ては [story-pipeline.md](../spec/story-pipeline.md) §8 と [scale.md](../spec/scale.md) §6 に定める。
