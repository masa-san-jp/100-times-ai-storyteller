# ADR-0010：先にプロットを作り、出来事はプロットから作る（本来の思想に戻す）

- 状態：Superseded by ADR-0011
- 日付：2026-10-18

## 背景
このシリーズの思想は、先にプロット（物語全体の骨格）を作り、そこから個々の出来事を作ることである。先行シリーズ（heros-journey）もそうしていた。ところが、このリポジトリの最初の設計文書（2026-09-27、`aa9064d`）は、プロットを作る工程を「出来事を1件ずつ作る方式」に置き換え、設計原則 P1 に「最終的な物語の姿をカードに含めない」と書き込んだ。これは所有者の思想から外れた変更であり、この ADR はそれを本来の思想に戻す。所有者は 2026-10-18 に「先にプロットを作ってから個々の出来事を作っているのではないのか。そのような思想のはずだ」と示した。


v0.0.1 で作った作例（Ollama で動かした gpt-oss:20b、入力2行、いちばん小さい規模）は、物語になっていなかった。
- プロットの3つの出来事が、どれも「橋の幅が広がるのを観察して記録した」という同じ行動だった。何も破れず、誰も変わらず、問いも立たない。
- 小説は、その3件を字数の下限まで引き延ばしたもので、人物の肩書きや世界の仕組みを読み上げる文章になった。

原因は、どのモデル・何回の実行でも同じになる、設計そのものにある。
1. 設計原則 P1 は「LLMに全体像を見せない。最終的な物語の姿をカードに含めない」と定めている。この原則を、物語の全体像そのものを作らないことと取り違えた。
2. 先行シリーズ（heros-journey）が出来事の前に作っていたもの（物語の骨子A〜E、物語全体のあらすじ、段階ごとの具体的な説明）を、取り込みの時点で「出来事を1件ずつ作る方式に置き換える」として外した（[lineage-inventory.md](../lineage-inventory.md) §7・§8）。
3. 出来事を作るカードは、物語全体の計画と、入力にない事実を加えることを禁じている（[story-pipeline.md](../spec/story-pipeline.md) S7）。出来事を作るAIが受け取るのは、直前の出来事の結果、プロットの型の一般的な説明文、世界の仕組み（筋の条件）だけである。
4. その結果、この物語で何が破れ、誰がどう体験し、何が変わり、どう終わるかを決める工程が、手順のどこにもない。出来事は目指す先を持たず、手元の材料（世界の仕組み）をなぞるしかない。
5. 検査は矛盾・繰り返し・字数・主語の名前など、あってはならないことだけを見ている。物語が進んでいるかを確かめる検査がない。これまでの品質の問題（同じ出来事の言い直し、結末が段階の達成宣言だけになる、など）は、この欠落の症状だった。それを個別の禁止と検査で塞いできたため、出来事を作るAIに許すことがさらに狭まった。

## 判断

### 1. 物語の定義
このハーネスが作る物語は、少なくとも次を備える。根拠は末尾の「出典」に示す。［原典］は原典の本文で確かめたもの、［二次］は原典を引用した二次資料で確かめたもの。
1. **秩序の破れ**：人物にとって当たり前の秩序（正典的な筋書き）があり、それが破れる。語る価値は、この破れから生まれる（ブルーナー［原典］）。対立は破れの一種であり、対立のない型（起承転結、抒情、日常など）も破れは持つ。安定した状態が乱され、別の新しい均衡に至るという整理もある（トドロフ［二次］）。
2. **体験する人物**：破れを、固有の動機と立場を持つ人物が体験する。出来事は、人物が知覚し、感じ、選ぶものとして書く。筋のない物語はありうるが、人間の体験を欠く物語はありえない、という立場を採る（フルデルニク［二次］。これに反論する論者もいる）。
3. **変化**：出来事は、前の出来事の必然または蓋然の帰結としてつながる。破れを経て、状態が反対へ転じる（逆転）か、無知から知へ移る（認知）（アリストテレス［原典］）。
4. **問いと結末**：物語の中で問いが立ち、物語が立てた主要な問いに答えが出たとき、終わりが感じられる（キャロル［二次］）。物語が扱う人間に普遍的な問い（例：秩序と自由、個と共同体）は、答えを示すか、正しく立てたまま読者に渡す。芸術家の義務は問いを解くことではなく、正しく立てることである（チェーホフ［原典］）。複数の人物の声を、どれか1つを正解とせずに並べることもできる（バフチン［二次］）。
5. **語りの順**：何をいつ読者に明かすかで、好奇心（過去の欠けた情報への関心）、サスペンス（未来への関心）、驚きを生む（スタンバーグ［二次］）。
6. **核と触媒**：出来事には、物語の行方の選択を開閉する核と、その間を満たす触媒がある（バルト［二次］）。変化を求めるのは核の出来事である。

ユーザーの入力は、普遍的な問いをどの切り口で、どんな人物と世界で具体化するかを与える。プロットの型は、骨格を組み立てる型紙として使う。

### 2. 設計原則 P1 を改める
- 改める前：「LLMに全体像を見せない。パイプライン全体、他のタスク、最終的な物語の姿を、タスクカードに含めない。」
- 改めた後：「LLMにパイプライン全体と他のタスクを見せない。物語は、先にプロット（物語全体の骨格）を分解した工程で作り、個々の出来事はそこから作る。各カードには、その要素がプロットの中で担う役割を含める。」
- 「LLMは作者ではない」「1回の推論で1つの要素」（ADR-0008）は変えない。骨格も、要素ごとの推論に分けて作る。

### 3. 骨格を作る工程を、出来事の前に置く
人物と世界の設定の後、出来事の前に、物語の骨格を作る。骨格は次の要素からなり、上の要素を参照して下の要素を作る。
1. 普遍的な問いと、入力から読み取る切り口
2. 当たり前の秩序と、その破れ
3. 主要な人物それぞれの立場（普遍的な問いへの、その人物なりの答え）と動機
4. 物語の中の問いと、結末（問いへの答え、そこで変わったもの、普遍的な問いへの示し方）
5. プロットの型の段階ごとの核の出来事の役割（結末から逆算し、各核で何が新しく起き、何が変わるか）
6. 語りの順（各核で、読者に何を明かし、何を伏せるか）

### 4. 出来事を作るときの決まりを改める
- 出来事を作るカードには、骨格のうち、その出来事が担う役割と結末を含める。
- 「物語全体の計画を許可しない」「入力にない事実を加えない」を削除する。代わりに「確定した設定・前の出来事と矛盾しない範囲で、役割を果たす新しい出来事・発見・人物の行動を加えてよい」とする。
- 核の出来事は、前の核から何が変わったかを持たなければならない。変化がなければ不合格とする。

### 5. 筋の条件の位置づけを改める
筋の条件（発動・禁止・解決）は、骨格に従う制約として扱う。出来事の中身の材料としては使わない。

## 理由
- 物語の骨格がなければ、どれだけ出来事を検査しても、物語は生まれない。今回の作例と、これまでの品質の問題がそれを示している。
- P1 の本来の目的は、LLMの持つ平均的な知識に物語を任せず、ユーザーの入力と要素テーブルから物語を作ることにある。骨格を入力とテーブルから分解した工程で作れば、この目的と両立する。
- 小さな推論に区切ることと、ゴールに向かって作ることは両立する。上位の決定を各推論に渡せばよい。言語モデルで長い物語を作る研究でも、全体の計画を先に作り、それを各段の生成に渡す方式が、計画しない生成より、筋の一貫性と前提との関連性で人の評価が高かった（Re3［原典］、DOC［原典］）。
- 登場人物の目標に沿った行動だけを一歩ずつ模倣する方式は、物語にならない出力を多く生んだ（TALE-SPIN［二次］）。現在の設計は、これと同じ構造である。

## 影響
- VISION P1 の文言を改める。
- LINEAGE・lineage-inventory で「外す」とした骨子A〜E、物語全体のあらすじ、段階ごとの具体的な説明を、骨格の工程の材料として見直す。ただし、先行シリーズの定義を正解としては扱わない。
- story-pipeline：骨格の工程を加え、出来事の生成（S7）の決まり、筋の条件（§9.5）、整合確認（S8）を改める。
- 様式化：小説などのカードにも、骨格のうち、その部分が担う役割と語りの順を渡す。
- 既存の run には適用しない。版を上げ、キャッシュを分ける。

## 未確認の点
- ［二次］とした項目は、原典の本文と頁を確かめていない。引用や頁を仕様に書く前に原典で確かめる。
- 骨格の各要素を作るカードの文面と検査は、この ADR の承認後に仕様として定める。
