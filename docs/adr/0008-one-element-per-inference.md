# ADR-0008：1回の推論で1つの要素だけを作る

- 状態：Accepted
- 日付：2026-10-07

## 背景
実機の run（gpt-oss:20b、短編）で、世界の事実のタスク（S4.facts）が5回不合格になり、run が止まった。このタスクは1回の推論で、事実の行を最大6件、新しい固有名詞とその読み、出典 ID をまとめて出させていた。固有名詞の読みが1件だけ規則に合わないと、正しく書けていた事実もすべて捨てて推論し直していた。出典 ID は、カードに渡した素材の ID でありコードが決められるのに、LLM に書かせていたため、出力例の ID を写すなどの誤りが不合格の原因になった。同じ量（丘の標高など）を別々の推論が作り、値が食い違った。

所有者は次のように指摘した：LLM が推論している以上、完全な構造化出力はできない。失敗した出力を推論し直せるよう、1つの要素について1回の推論となるハーネスであるべきである。

## 判断
- LLM タスク1つは、1つの要素だけを作る。要素の形は [task-model.md](../spec/task-model.md) §2.5 に定める（本文1つ、値1つ、名前と読み、分類つきの項目1つ、一覧からの選択、判定と理由）。
- 複数の要素からなる構造（事実の表、5W1H の出来事、人物の事実のシートなど）は、要素ごとのタスクに分け、コードが組み立てる。
- 出典（`sources`）は LLM に書かせない。カードの「入力」節に示した素材の ID を、コードが記録する（P3 の改訂）。
- 同じ値（同じ量・同じ名前）は、1つのタスクで1回だけ作り、他の箇所は入力として参照する。
- 再試行と失敗は要素1つの単位で起き、他の要素の結果を捨てない。

## 理由
- 推論の失敗を要素1つに閉じ込め、正しく書けた要素を捨てずに済む。
- 1回の推論が小さくなり、小さいローカルモデルで完走しやすくなる（P5）。
- コードで決められるもの（ID、出典、暦の名前、派生値、並び順、組み立て）を推論から外すことで、誤りの入り口を減らす（P2）。

## 影響
- [VISION.md](../VISION.md) の P1 に要素の単位を加え、P3 の出典の記録をコードに移す。
- LLM タスクの数は増える。1回の推論は短くなる。
- 既存のタスクのうち、複数の要素を出していたもの（S1.extract、S2.expand、S4.facts、S5.facts、S7.event と、`sources` を出力に持つタスク）を、[story-pipeline.md](../spec/story-pipeline.md) に従って分ける（Phase 1 の P1-30〜P1-34）。
