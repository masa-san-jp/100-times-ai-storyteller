# ADR-0003：人が書くファイルは YAML、機械が書くファイルは JSON

- 状態：Accepted
- 日付：2026-09-26

## 背景
タスク定義・テーブル・様式プロファイル・manifest・出力の書式を決める必要があった。[ADR-0002](0002-python-uv.md) で外部ライブラリの利用を認めたため、YAML を読める。

## 判断
- 人が書いて保守するファイル（タスク定義、テーブル、様式プロファイル、モデル設定）は YAML とする。
- オーケストレータが書き出すファイル（manifest、タスクの入出力、正本、キャッシュ）は JSON とする。
- YAML は `yaml.safe_load` で読み、読み込んだ直後に JSON Schema で検証する。

## 理由
- タスクの手順や要素テーブルは、物語の素材そのものであり、人が推敲する。YAML は複数行の文章とコメントを自然に書ける。
- 先行リポジトリ（world-building）のプロンプトは YAML で書かれており、取り込みやすい。
- JSON は LLM の出力形式と一致し、標準ライブラリで読み書きできる。
- YAML には、`yes` / `no` / `on` / `off` などが文字列ではなく真偽値として読まれる弱点がある。読み込み直後の JSON Schema 検証で型の誤りを検出して防ぐ。

## 検討した他の案
- TOML：標準ライブラリで読めることが利点だったが、ADR-0002 でその利点が失われた。長い文章と入れ子の構造は YAML の方が書きやすい。
- 手順の文章だけを Markdown にする：1つのタスクが2ファイルに分かれ、保守の単位が曖昧になるため採らない。

## 影響
- 各 YAML ファイルの種類ごとに、JSON Schema を `schemas/` に置く。
