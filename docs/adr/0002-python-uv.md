# ADR-0002：Python と uv で実装し、依存関係の導入をリポジトリに含める

- 状態：Accepted
- 日付：2026-09-26

## 背景
利用者は macOS 以外（Windows・Linux）も使う。必要な依存関係のインストールは、リポジトリの手順に含める。実行者（エージェント・ローカルLLMの実行環境）が、同じ手順で同じ環境を得られる必要がある。

## 判断
- 実装言語は Python とし、必要なバージョンは 3.11 以上とする。
- 環境の構築には [uv](https://docs.astral.sh/uv/) を使う。`pyproject.toml` と `uv.lock` をリポジトリに含める。
- 外部ライブラリは、必要性を説明できるものだけを使う。導入時点で使うのは次の2つとする。
  - `PyYAML`：人が書くファイル（[ADR-0003](0003-yaml-and-json.md)）の読み込み
  - `jsonschema`：タスク出力・タスク定義・正本の検証
- 開発用の依存は `pytest` とする。
- ライブラリを追加するときは、この ADR の「判断」節に追記し、理由を書く。

## 理由
- Windows には Python が標準では入っておらず、macOS の標準の Python は 3.11 より古いことがある。どの案を選んでもインストール手順は必要になるので、「標準ライブラリだけならインストール不要」という利点は成り立たない。
- uv は macOS・Linux・Windows で同じ手順で動き、必要なバージョンの Python 自体も取得する。`uv.lock` によって、全員・全実行者が同じバージョンの依存関係を使う。
- 形式検証を自前で実装すると、検証の不備がそのまま生成物の品質の問題になる。実績のあるライブラリを使う。
- 先行3リポジトリと同じ言語であり、定義や知見を移しやすく、改修に参加できる人が多い。

## 検討した他の案
- Python 標準ライブラリのみ：インストール手順が結局必要であり、検証の自前実装という欠点だけが残るため採らない。
- Go などの単一の実行ファイル：配布は最も簡単だが、先行リポジトリとの連続性と、改修に参加できる人の範囲を失うため採らない。

## 影響
- セットアップ手順は「uv を導入する → `uv sync`」とし、README に OS ごとの uv の導入方法を書く。
- `pyproject.toml` は、uv を使わない人のために `pip install -e .` でも導入できる形にする。
- コマンドの入口は `pyproject.toml` の `[project.scripts]` に登録した `st` に統一し、OS 依存のシェルスクリプトを置かない。開発者はリポジトリ内で `uv run st` として、実行者は `uv tool install --editable` で導入した `st` として使う（2026-09-27 明確化：判断の内容は変えず、実行者の導入方法を明記した）。
- 複数の OS で動かすため、実装は次に従う：パスは `pathlib` で扱う／ファイルは常に `encoding="utf-8"` を指定して開く／改行コードは LF で書き出す／ファイルのロックは `os.open(..., O_CREAT | O_EXCL)` で行う。
- CI（GitHub Actions）で、macOS・Linux・Windows のテストを実行する。
