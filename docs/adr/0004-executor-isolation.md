# ADR-0004：実行者の隔離を、配置と権限設定の両方で担保する

- 状態：Accepted
- 日付：2026-09-26

## 背景
実行者に全体像を見せないこと（P1）が原則である。一方、多くのコーディングエージェントは、作業ディレクトリとその親ディレクトリにある `AGENTS.md` / `CLAUDE.md` を自動で読み込む。リポジトリ内で実行者を動かすと、開発者向けの文書（全体設計を含む）が実行者の文脈に入ってしまう。また、配置を分けても、エージェントが自分からリポジトリのファイルを開くことは技術的に可能である。

## 判断
1. リポジトリのルートの `AGENTS.md` / `CLAUDE.md` は、開発者向けとする。
2. 実行者は、`st workspace init` でリポジトリの外に作ったワークスペースで動かす。ワークスペースには、実行者プロトコルだけを書いた `AGENTS.md` / `CLAUDE.md` を置く。
3. `st workspace init` は、対応するエージェント製品ごとに、ワークスペースの外（リポジトリ・データディレクトリ）の読み取りを禁止する権限設定を書き出す。実行者がタスクに必要とするのは `st` の実行だけである。
4. 権限設定に対応していない実行者は、「配置による隔離のみ」の実行者として扱い、`st status` と manifest にその旨を記録する。

## 理由
- 規約（「リポジトリを読まない」）だけでは、自動読み込みも、意図的な読み取りも防げない。
- LLMの内部推論による全体の推論を排除することは、この作品の核である。実行者の善意に頼らず、仕組みで担保する。

## 検討した他の案
- 規約だけ：自動読み込みを防げないため採らない。
- 配置だけ：意図的な読み取りを防げないため、単独では採らない（権限設定に対応しない実行者の下限としてのみ残す）。

## 影響
- `st workspace init` は、リポジトリの内側のパスを拒否する（[cli.md](../spec/cli.md)）。
- 実行者プロトコルの原本は [executor-protocol.md](../spec/executor-protocol.md) とし、ワークスペースのテンプレートはそこから作る。
- 対応する製品と権限設定の具体的な書き方は、Phase 1 で実機検証した上で [architecture.md](../spec/architecture.md) §4 に記載する。最初の対応対象は Claude Code と Codex とする。
